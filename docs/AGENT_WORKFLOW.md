# 可交给 Codex 的执行工作流

将下面这段作为任务要求，或让 Codex 读取本文件后执行。

> 在这台 Mac 上配置“官方 ChatGPT 手机端 → 官方桌面端 → 现有 API 网关”的混合登录。
>
> 先阅读本仓库 README 和当前仓库 AGENTS.md。保留现有模型、推理强度、provider、历史会话和无关设置；不要安装额外远控软件，不修改生产服务器。
>
> 使用 `scripts/hybrid_remote.py`：
>
> 1. 运行 `doctor`，确认官方桌面 App、已有 API provider、OpenCodex 与 Python 版本。先看当前 Git 状态，不将用户配置复制到仓库。
> 2. 用 `login` 在隔离目录发起官方 OAuth。按用户指定的 Chrome profile 打开页面，用户在官方界面完成登录。密码、验证码和 OAuth URL 不进入聊天或日志。
> 3. 运行 `plan`；若存在多个 API provider，只询问真正影响目标的选择。对用户已授权的修改直接执行，不重复问许可。
> 4. 运行 `apply`，记录私密备份路径。发生任何冲突或中途失败时先检查阶段记录，不反复覆盖。
> 5. 运行 `verify`，验证自定义和内置两条请求路径。核对 OpenCodex Usage 中实际 provider 和 HTTP 状态。只报告通过的检查。
> 6. 在用户授权重开应用后运行 `restart`。重开后复查官方账号与 API 配置，分别测试原生 Computer Use 和浏览器扩展通道。
> 7. 在官方桌面设置中完成“连接 → 控制此 Mac”；由用户用手机扫码。配对二维码和链接不写进任何公开内容。
> 8. 请用户从手机发起一个只读本机任务，确认在目标 Mac 执行，并核对对应 API 用量。区分“用户确认手机可用”和“日志证实该条手机任务走中转”。
> 9. 恢复任务期间临时开启的 AppleScript 网页 JavaScript 等设置；保留用户原有剪贴板。不要关闭用户的账号页面或清理无关进程。
> 10. 交付：实际改动、验证结果、未完成项、回滚路径。没有手机实测时不能声称全链路完成；浏览器扩展仍报错时不能声称已修复。
>
> 凭据只能从用户已授权的本机私密配置读取并直接写入本机私密文件。禁止展示密钥、JWT、Cookie、手机号、短信码或账号个人信息。不要改程序二进制或绕过认证/工具授权检查。

## 决策边界

- 已有健康的 OpenCodex：复用，使用管理 API。
- 不存在兼容的 OpenCodex：说明前置条件，先安装用户认可的版本；不要盲目套用本脚本。
- 模型已被其他 combo 使用：显式选择已有 combo，或让用户决定冲突的目标。
- 自定义 provider 使用环境变量密钥、多行 TOML、不同 wire API 等本脚本未支持的形态：保留配置并解释具体不兼容点，不做猜测性改写。
- 手机或账号侧要求 MFA、通行密钥、验证码：用户在官方界面完成；无需将内容交给 Codex。
- 修改公开仓库：仅提交本工作流代码、脱敏文档和虚构测试数据。
